# Primary Workflow

1. Read `README.md`, `AGENTS.md` / `CLAUDE.md`, and relevant files in `./docs/`.
2. Define clear success criteria and state explicit assumptions before writing code.
3. Implement surgical, minimal code edits that satisfy requested behavior.
4. Keep Dart source files modular and under 300 lines.
5. Update documentation under `./docs/` when project structure, APIs, or architectural decisions change.
6. Verify implementation by running `flutter analyze` and `flutter test`.
7. Summarize results, verification status, and any remaining open questions.
